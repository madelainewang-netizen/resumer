# Resumer AI 产品案例页设计

## 目标

为 Resumer 增加一个可独立访问、也方便嵌入个人网站的产品案例页。页面面向招聘 HR 和 AI 产品岗位面试官，核心任务不是宣传简历工具本身，而是展示项目作者如何从个人求职问题出发，完成用户判断、产品设计、AI 工作流、技术落地和迭代验证。

案例页地址为 `/case-study`，现有工作台继续使用 `/`，两者部署在同一个 Vercel 项目中。

## 核心叙事

主标题：

> 一个文科生的 AI 产品实验

核心钩子：

> 为了找一份 AI 产品工作，我先做了一个帮自己找工作的 AI 产品。

叙事语气保持真实、克制、有一点自嘲，但产品判断清楚。页面避免使用“颠覆”“赋能”“重新定义”等营销式措辞，也不把个人体验包装成已经验证的市场结论。

## 目标用户与产品定位

Resumer 第一阶段面向正在集中求职的在校生和应届毕业生。他们通常只有一份基础简历，却要面对多个要求不同的岗位，并存在以下困难：

- 实习、课程项目和校园经历较为零散。
- 不知道招聘方真正关注哪些能力证据。
- 面对不同 JD 时只会机械替换关键词。
- 不擅长将过程描述为具体行动和结果。
- 容易使用同一份简历投递所有岗位。
- 担心 AI 润色夸大或捏造经历。

产品定位：

> Resumer 是一款面向在校生和应届生的 AI 简历定制工作台。它根据目标 JD，帮助用户找到值得强调的真实经历，并生成可逐条确认的定制简历。

“提升面试邀请率”属于后续需要验证的产品目标，不在当前案例页中作为已实现的结果承诺。

## 页面信息架构

### 1. 首屏

- 展示案例标签、主标题和核心钩子。
- 简短说明项目由作者独立完成问题定义、产品设计、AI 工作流和开发上线。
- 提供“体验产品”“阅读案例”和“查看 GitHub”三个入口。
- 右侧展示从原始简历到定制表达的流程缩影，而不是普通后台截图。

### 2. 项目起点

标题：

> 它最初不是一个创业点子，只是我想让改简历这件事简单一点。

说明作者在准备转行时，需要针对每个新 JD 重新理解要求、筛选经历、修改表达和压缩版面。由此提出初始问题：AI 是否可以先帮助用户理解岗位和找回真实证据，而不是直接改写文字。

### 3. 从个人困扰到用户假设

将个人经历扩展为面向在校生和应届生的用户假设，并以用户画像卡片呈现典型背景、任务、阻碍和顾虑。

明确标注这是基于个人经验与案头研究形成的第一版假设，后续仍需真实用户访谈验证。

### 4. 案头研究与竞品观察

围绕用户任务比较三类替代方案：

- 通用 AI 对话工具：灵活，但依赖用户自行设计 Prompt，输出结构不稳定。
- 模板型简历工具：排版成熟，但对不同 JD 的内容决策支持有限。
- ATS 匹配工具：强调关键词覆盖，可能让用户过度追求分数。

研究结论聚焦产品机会，不展示无法支撑的市场规模或效果数据。核心机会是将 JD 理解、经历选择、证据补充、内容改写和一页精简连接成连续工作流。

### 5. 产品闭环

使用贯穿页面的“职业证据链”作为标志性视觉元素：

`岗位要求 → 经历缺口 → AI 追问 → 真实证据 → 定制表达`

每一步说明用户输入、AI 的作用以及用户保留的控制权。

### 6. 关键产品决策

重点展示三个产品判断：

1. 先挖掘证据，再改写简历。
2. 真实性优先于匹配分数，缺少证据时明确暴露缺口。
3. 用户逐条确认、删除、恢复和反悔，AI 不直接覆盖原始内容。

同时说明文本匹配分只表示内容覆盖程度，不代表面试或录用概率。

### 7. 可交互产品体验

在案例页中嵌入 `/?demo=1&embed=1` 演示工作台。默认以浏览器窗口容器展示，并提供“展开体验”和“新窗口打开”操作。

iframe 加载失败时显示简短说明，并提供打开完整产品的备用按钮。

### 8. 迭代过程

以时间线或版本记录展示真实迭代：

- 从手动填写扩展到 PDF 结构化导入。
- 从直接改写扩展到经历缺口和 AI 引导提问。
- 从一次性优化扩展到逐条采用、删除和恢复。
- 根据真实简历测试调整 A4 密度、照片缩放和版式。
- 处理 Vercel 权限、PDF worker 打包和线上诊断问题。

### 9. 作者职责与技术理解

产品侧包括问题定义、MVP 范围、信息架构、交互设计、Prompt 与结构化输出、测试和迭代。

技术侧包括 React、Tailwind CSS、DeepSeek API、PDF 解析与生成、本地存储、Vercel Functions 和生产部署。

技术栈用于证明作者具备落地和排查能力，不喧宾夺主。

### 10. 复盘与下一步

当前结论限定为“完成可运行 MVP，并通过作者自己的真实简历完成端到端测试”。下一阶段计划邀请在校生和应届生测试，关注：

- 首次完成定制简历所需时间。
- AI 建议采用率与恢复率。
- 用户补充有效经历证据的比例。
- 导出完成率。
- 在足够样本和可控条件下观察面试邀请率变化。

页面结尾提供产品链接和 GitHub 链接。个人联系方式由个人网站统一承载，案例页本身不重复收集联系信息。

## 技术架构

项目继续使用单个 React/Vite 入口，不引入路由依赖。

- `window.location.pathname === "/case-study"` 时渲染案例页。
- 其他路径渲染现有 Resumer 工作台。
- `demo=1` 启用演示数据模式。
- `embed=1` 启用适合 iframe 的紧凑外壳。

案例页组件与工作台组件保持分离。案例页只依赖静态案例内容和演示 iframe，不读取简历 localStorage。

## 演示模式

演示模式使用一名虚构、脱敏的应届生案例，目标岗位为 AI 产品助理或初级产品经理。数据包括：

- 基础简历、实习、课程项目和校园经历。
- 一份目标 JD。
- 预置 JD 分析、匹配缺口和引导问题。
- 预置优化建议和最终简历。

演示模式约束：

- 状态仅保存在当前 React 内存中。
- 不读取、写入或覆盖访问者的 localStorage。
- 不调用 DeepSeek 或其他付费 API。
- HR 可以切换步骤、编辑内容和采用建议。
- 刷新页面后恢复演示初始状态。
- 提供“使用自己的简历”入口，打开正常工作台。

## 视觉设计

### 颜色

- Paper：`#FFFFFF`
- Canvas：`#F6F7F8`
- Ink：`#171717`
- Muted：`#6B7280`
- Hairline：`#E5E7EB`
- Evidence Blue：`#2563EB`

### 字体

- 中文和正文：现有 `Noto Sans SC` / 系统无衬线字体。
- 英文标签和数据：Inter / 系统无衬线字体。
- 主标题通过字重、宽度和断行形成个性，不额外引入网络字体。

### 布局

- 桌面内容最大宽度约 1180px。
- 首屏采用非对称两栏布局，文字约占 45%，产品流程缩影约占 55%。
- 正文以单列阅读为主，在用户画像、竞品观察和职责模块使用受控网格。
- iframe 使用浅灰浏览器边框和固定初始高度，支持展开。
- 移动端改为单列，iframe 使用内部滚动并提供新窗口入口。

### 标志性元素

“职业证据链”是全页唯一高辨识度视觉元素。蓝色连接线和节点只用于表达从岗位要求到真实证据的逻辑，不作为无意义装饰。

动效保持克制：首屏内容轻微进入、证据链按顺序显现、按钮和卡片提供轻量反馈，并尊重 `prefers-reduced-motion`。

## 错误与边界处理

- iframe 加载失败时显示备用链接。
- 演示数据异常时回退到只读案例预览，不影响案例页其余内容。
- 案例页不调用 AI，因此不展示 API 错误状态。
- 正常工作台的错误处理维持现有逻辑。

## 测试与验收

### 自动化测试

- `/` 选择现有工作台。
- `/case-study` 选择案例页。
- `demo=1` 使用演示状态，且不调用真实存储读写函数。
- `embed=1` 渲染紧凑外壳和“使用自己的简历”入口。
- 案例页包含产品、GitHub 和 iframe 备用入口。

### 手动验收

- 桌面端检查首屏层级、长页节奏和 iframe 展开行为。
- 移动端检查单列布局、字号、横向溢出和 iframe 操作。
- 验证 iframe 内演示工作台可切换步骤并在刷新后复位。
- 验证正常工作台原有资料、localStorage 和 API 流程不受影响。
- 运行完整 `npm test` 和 `npm run build`。

## 非目标

本阶段不包含：

- CMS 或后台编辑系统。
- 真实用户登录与云端演示数据。
- 自动收集分析数据或面邀率。
- 多个案例页模板。
- 将案例页作为 Resumer 默认首页。
